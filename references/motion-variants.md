# 四种可选空间转场

在独立 scene JSON 中设置 `motionVariant`。这些方案使用同一组彩色分层底稿和连续相机；主体都留出 `alignedHoldSeconds` 的阅读时间，默认 1.2 秒。不要把五猫的参数自动视为所有素材都适用。

| 值 | 空间与表现 |
|---|---|
| `fold` | 分层画面绕相邻边缘翻开，绘画层略微错开，像透明折页。相机横向移动并略微升高。 |
| `dive` | 主体沿纵深排开，镜头向前进入笔层，带小幅轴向旋转；下一主体从深处放大。 |
| `cube` | 主体位于相互正交的墙面、顶部、底部，镜头转向时拉开以看见多个朝向。最多 5 个主体。 |
| `bloom` | 冷暖笔层各自位移、旋转、淡出；下一组笔层从分散状态聚拢，配合镜头放大。 |

```json
{
  "motionVariant": "fold",
  "alignedHoldSeconds": 1.2,
  "outroTitle": "猫 的 另 一 面",
  "outroSubtitle": "HINGED INK"
}
```

沿用通常的 `build_v2.py --mode generic --scene scene.json` 与导出命令。转场模式自行定义布局、相机和末尾，因此该 JSON 不混用原路径的 `families`、`accents`、`ending`。原路径省略 `motionVariant`；原猫示例的毛线仅属于原路径。

`cube` 保持绘画面位置固定；其他模式显式移动或旋转绘画面，也会调整透明度。每层贴图身份始终不变。用户要翻转/淡化时，不能拿早先的“物体必须完全固定”限制拒绝这些方向。

先查每次过渡的连续帧，尤其检查正交模式的画面留白、相机背后曲面穿入镜头，以及放大时稀疏笔层是否盖住下一主体。完整对齐段必须稳定，快速段不必让每一帧都拼成完整头像。各版本属于待用户选择的创意实验，不自动继承原人像影片的主观认可。
